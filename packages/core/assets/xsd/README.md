# SRI schemas

The XSDs exactly as SRI publishes them. They are the source: the code embeds each one in `src/sri/xsd/` (generated by `pnpm --filter @comprobify/core xsd:embed`), and `xsd-assets.test.ts` fails when a copy differs from its file here. Never edit one by hand.

| File | Document | Used |
|---|---|---|
| `factura_V2.1.0.xsd` | Factura (01) | Yes |
| `nota_credito_V1.1.0.xsd` | Nota de crédito (04) | Milestone 4 |
| `guia_remision_V1.1.0.xsd` | Guía de remisión (06) | Milestone 4 |
| `xmldsig-core-schema.xsd` | XML signature, imported by the others | Yes |

`guia_remision_V1.1.0.xsd` (06) is stored with LF line endings: SRI's file has CRLF, which a JavaScript template string reads as LF anyway, so the embedded copy could not otherwise be identical. The XML is the same. Where a widened pattern is needed, as for the RIMPE legend (ADR-013), the code widens it when the schema loads and this file stays as published.
